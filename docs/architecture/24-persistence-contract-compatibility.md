# M1.3.1 persistence contract compatibility

## Persisted formats retained

| Record | Schema / location | Restore and error behavior |
| --- | --- | --- |
| Materialized Store state | `state.json`, `universal-store/v1` | JSON decode errors and unsupported schema return an error; resident metadata is validated after decode. |
| Journal record | `journal.jsonl`, `universal-store/v1` | Append is synced before materialized state replacement. Invalid lines or commits fail open/replay with an error. |
| Archived journal segments | `segments/*.jsonl`, same record schema | Records are validated and ordered by revision; corruption fails validation. |
| Cognitive snapshots | `cognitive-snapshot/v1`, `/v2`, `/v3` within existing records/qualification fixtures | Existing cognitive normalizers, validators and feature-order checks remain authoritative. |
| Decisions and action work | `cognitive-decision/v1`, existing V3 decision JSON, `ActionRequest` fields | Existing `omitempty`, float widths, field names and dry-run/action semantics remain unchanged. |
| Resident projection | `face-gallery-policy/v1` inside `universal-store/v1` | Same fields, tags, timestamp type and policy version; restore validates opaque refs, status, policy, redaction and timestamps. |
| Erase recovery marker | `erase.marker`, `universal-store/erase/v1` | Marker is synced before history deletion; interrupted erase is recovered at open. |

No schema version, path, ordering rule, migration, or production data was
changed. `ResidentGalleryRecord` moved as a Go definition only; disk encoding
continues to use the same field declarations, order, types, and tags. The
historical cognitivecore type spelling aliases that definition.

## Fixture provenance

There are no historical production state or journal fixtures in the
workspace. Existing snapshot, journal and decision compatibility tests use
synthetic/test fixtures generated by the repository's prior implementation
or explicit in-test values; none were read from production. The new resident
record golden JSON is pinned from the pre-extraction field tags and
`time.Time` JSON format. It is synthetic and intentionally contains no
resident identity or biometric data.

## Compatibility checks

The Foundation contracts package tests exact resident-record JSON bytes for
the common field set, restores that JSON and validates the result, and checks
that optional `last_error_category` and `deleted` remain omitted when empty
and present when populated. It also checks that the zero `gallery_generation`
remains present (it has no `omitempty`). Existing cognitivecore tests retain
coverage for resident validation and Store persistence/restart.

The existing suite also covers V2/V3 snapshot golden vectors, immutable V2
feature prefix, canonical snapshot equality around compaction, restart and
journal replay, duplicate commits, outbox state, malformed records, corrupt
archive rejection and erase recovery. Existing decision serialization is
exercised through persisted commits and Store tests; the decision structs and
serializers were not modified in this milestone.

Byte comparisons apply to the new resident JSON golden. Other compatibility
checks use exact canonical JSON or structural assertions as their existing
test contracts prescribe. No artificial promise of byte-for-byte ordering
for arbitrary map keys is introduced.

## Limits

The extraction tests validate the contract Go type and the unchanged suite
validates Store use. They do not establish compatibility against unknown
historical production files. No production restore, migration, write, or
service restart was performed. The Store journal and snapshot serializers
remain in cognitivecore pending a later contract design that resolves their
Intelligence type dependencies.

## M1.3.2 implementation ownership update

The serializers, state envelope, journal envelope, restore, replay, WAL,
compaction and erase recovery are now implemented in Foundation statestore.
The concrete snapshot/decision/action values continue to be the existing
Intelligence record types supplied through compile-time generic parameters.
The `cognitivecore` Store API delegates to that implementation and performs
V3 snapshot projection. The persisted schema, paths and tags remain unchanged;
see `26-universal-store-extraction.md` and `30-m132-validation.md`.
