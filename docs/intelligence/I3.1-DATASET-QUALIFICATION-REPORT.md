## Contract versions and actual target definitions

- Dataset: `synora.cognitive-dataset/v1`
- Generator: `1.0.0`
- Input batch: `synora.observation-batch/v1`
- State Encoder: `synora.state-encoder/v1`, version `1.0.0`
- Five labels are emitted on every generated example.
- A and B use `cutoff + 1 minute`; C and D also declare `cutoff + 1 minute`; E declares the cutoff.
- In code, A is the Boolean hidden `after` state; B is the transition between hidden `before` and `after`; C is `edge_added` iff the fixture contains a future edge; D follows the hardcoded synthetic anomaly flag; E is `inconsistent` iff the conflicting-source fixture sets `consistent=false`.

These are the actual mechanics, not endorsement of their task validity. A/B's definitions do not identify the target entity/attribute in `TaskLabel`. The selected `room` comes from a random schedule stream, the ordinary source observation refers to `home.sensors[0]`, and the truth event's `EntityID` is the selected room (except the lighting case, where it is a device). For multiple-occupant and several fault scenarios, the label is still only one Boolean state. The code does not establish an entity mapping from that observation to the target. Task B additionally has no transition-time bin or event-time target.

## Defect and disposition

**Defect:** A/B target contract is underspecified: target identity/attribute is absent from the label contract and is not consistently inferable from available observations. The same generic label can refer to different entity kinds/attributes, and the input observation may belong to another entity.

**Impact:** A score or diagnostic baseline would have no stable, declared prediction unit. Adding a target reference or changing the interpretation would change the task contract and potentially the model-facing schema.

**Correction:** None. The mission prohibits changing intended task meaning or redesigning the schema without approval. No code, dataset schema, generator behavior, or model was modified for I3.1.

**Decision required:** Define whether A/B predict (1) a specific entity/attribute supplied by each example, with an explicit target reference and eligibility policy, or (2) a home-level aggregate with a precise aggregation rule. Also define B's event/horizon semantics. After this decision, resume qualification with a versioned, owner-approved contract.
