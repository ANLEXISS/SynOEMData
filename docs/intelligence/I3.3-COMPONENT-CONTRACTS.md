**Status:** STRUCTURAL CONTRACTS IMPLEMENTED / TESTED / EXPERIMENTAL / REVIEW REQUIRED

## Common lifecycle and metadata

Every branch and cognitive head implements `ManagedComponent`: immutable `Metadata`, `Initialize(context.Context)`, and `Shutdown(context.Context)`. The in-process `Registry` tracks `initializing`, `ready`, `unavailable`, `failed`, and `stopped` states. It validates contract and schema compatibility before initialization and validates metadata stability at invocation. A runtime call error marks that component failed. Invocation is protected against concurrent replacement/shutdown.

Component identity, role, contract version, component version, input/output schema, representation space, execution class, and optional model version are separate metadata. Contract version must match `ArchitectureVersion`; component and trained-model versions use `major.minor.patch`. A trained component must provide a model version. A test fixture cannot be represented as a trained model. One component per role is selected by role; cognitive heads may be selected by role plus head kind.

Replacement initializes the new component before swapping it in, requires the same ID, role, and head kind, then shuts down the old component. If initialization fails, the old component remains registered. This procedure does not persist artifacts or perform rollback across process restart.

## Representation and fusion envelope

A `Representation` declares schema version, component reference, representation-space ID, runtime dimension, finite values, same-length validity mask, and optional evidence refs. Invalid dimensions, non-finite values, nonzero masked coordinates, or component/space mismatch are rejected.

General fusion has exactly two ordered contributions: Event then Topo-Temporal. Cognitive fusion nests the General envelope and has one Home contribution, which may explicitly be unavailable or failed. Each vector and mask remains independently addressable; no concatenation, shared coordinate system, learned fusion, or numerical combination is defined. Thus this is a deterministic structural envelope, not a fused cognitive vector.

## Cutoff and deterministic input handling

The decision cutoff applies to receipt/availability times. Event input positions must strictly increase. Observed time remains provenance and may be later than the cutoff. Topology entities and relations require receipt time no later than cutoff; known event locations require an eligible receipt time. The pipeline deep-copies inputs before calling components and sorts graph entities by ID, relations by their directed/source/valid-time/receipt-time key, and event locations by event position. It does not reorder event sequence positions.

## Test status and limitation

Synthetic fixtures in `hybrid_test.go` are deterministic test doubles and are the only executable branch implementations in this package. They are not trained models and must not be used as real predictions. Tests exercise registration, lifecycle, compatibility, deterministic ordering/fusion, cutoff validation, partial context, cold start, home failure isolation, replacement, and structural output limits. Neural numerical quality, model interoperability across implementations, runtime performance, and hardware support are NOT MEASURED.
