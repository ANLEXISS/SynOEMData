# I3.3 — Home Adaptation Lifecycle

**Status:** OPTIONAL BRANCH CONTRACT IMPLEMENTED / STRUCTURALLY TESTED / EXPERIMENTAL / REVIEW REQUIRED  
**Home model, adaptation policy, and learning:** NOT IMPLEMENTED

## Ownership boundary

The Home Adaptation branch is an optional Intelligence component that transforms General fusion into a household-specific context representation when an eligible adaptation is supplied. It does not own explicit household facts. Foundation StateStore/Home Memory remains authoritative. The contract carries an optional `MemoryVersion` as context metadata, but does not read or write that store.

An opaque `AdaptationRef` identifies supplied adaptation state without prescribing storage. `ModelVersion` identifies the model artifact; component and contract versions identify the adapter and interface. These version fields are not interchangeable.

## States

| State | Meaning | Pipeline behavior |
|---|---|---|
| `cold-start` | No household adaptation initialized | Skip Home branch; return General fusion and mark Home contribution unavailable with cold-start reason. |
| `unavailable` | Adaptation cannot currently be supplied | Skip Home branch and preserve General fusion. |
| `reset` | Caller declares an adaptation reset boundary | Skip Home branch and preserve General fusion. |
| `available` | Caller supplies an opaque adaptation ref, semantic model version, and training cutoff | Invoke the registered Home branch with a copy of General fusion and the explicit metadata. Reject if its training cutoff is later than the decision cutoff. |

If no Home component is registered, general cognition remains available and the Home contribution says so. If a registered Home component fails or is stopped, that failure is isolated to the Home contribution. The two required general branches remain mandatory.

## Data and time rules

The contract distinguishes adaptation reference, model version, explicit-memory version, and training cutoff. It does not define what household data may train weights, resident profiles, personalization policy, retention, consent, reset persistence, or update cadence. There is no online learning, weight update, automatic retraining, or model adaptation policy in I3.3. A later design needs explicit privacy, retention, opt-out, reset, provenance, and rollback decisions before household-specific training is authorized.

A Home implementation must only use information available by the decision cutoff. The current boundary checks that the declared training cutoff is not in the future; it cannot prove that referenced training data is causally clean. No household-specific data or model is present in I3.3 tests.

## Cold-start degradation

Cold-start and reset are supported without blocking Event and Topo-Temporal representations or General fusion. The output remains structural metadata and branch vectors; it does not claim assistance, safety, or a prediction. Cognitive heads are not run by the current orchestrator.
