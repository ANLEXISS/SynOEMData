# I3.3 — Preparation Notes for a Later I4 Review

**Status:** DESIGN NOTES ONLY / I4 NOT AUTHORIZED  
**I4 implementation, training, and model integration:** NOT AUTHORIZED

These notes identify evidence and decisions required before any later learned-model milestone. They do not authorize that work and do not resolve I3.1/I3.2 semantics.

## Suggested staged evaluation

1. **Baseline 0 — deterministic controls:** last-state/persistence, frequency or simple task-specific controls using frozen, qualified dataset contracts.
2. **Baseline 1 — existing isolated model:** evaluate a single legacy MLP only if its input/target contract is proven compatible. Do not silently translate its 86-value contract or I1 research labels.
3. **Baseline 2 — general branches:** compare Event-only, Topo-Temporal-only, and Event plus Topo-Temporal under the same homes, topology groups, cutoffs, and labels.
4. **Baseline 3 — optional Home branch:** compare cold-start/general-only with eligible home adaptation, using disjoint home groups and a declared data/time boundary.
5. **Baseline 4 — learned contextual fusion and heads:** consider only after structural inputs, baselines, leakage controls, and branch ablations are qualified. Compare against the I3.3 structural envelope; this would be a new learned design, not the current implementation.

No score, expected gain, runtime cost, or hardware estimate is supplied here. Measure parameter count, memory, latency, CPU load, failure rates, and device-specific behavior before selecting a runtime or accelerator.

## Required evaluation evidence

- Approved versioned task and target definitions, including target identity/eligibility, transition time/horizon, label availability, and missing-target policy.
- Dataset qualification, provenance, causal receipt-time cutoff, duplicates and conflict handling, and an independent leakage audit.
- Disjoint train/validation/test homes and topology families; separately held-out scenario templates and, where relevant, future periods. Fit vocabularies, mappings, and normalization on training groups only.
- Task-appropriate metrics with class/value distributions, per-class performance, calibration/uncertainty, abstention, subgroup/generalization results, and confidence intervals where supported by sample size.
- Ablations for each branch, missing/partial topology, missing history, home cold start/reset, sensor degradation, and deterministic fallback. Keep fixture results separate from trained inference.
- Reproducible artifact manifests, hashes, exact code/data/model versions, resource measurements on target hardware, and independent review before any Core integration proposal.

## Current prerequisites and boundaries

I3.1 qualification, Task A/B semantics, I3.2 grammar/dataset generation, scenario diversification, and leakage qualification are deferred. No mappings or labels were invented to make this architecture work. The current hybrid package has no training pipeline, neural inference, model bundle, learned fusion, head execution, Core dependency, or action behavior. Any future milestone requires separate owner authorization, including any training, model changes, production integration, commit, push, or publication.
