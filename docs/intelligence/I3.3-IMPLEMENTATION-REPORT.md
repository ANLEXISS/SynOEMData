## Summary

I3.3 adds an executable, model-independent architecture skeleton in `internal/intelligence/hybrid`. It provides distinct Event, Topo-Temporal, and optional Home Adaptation branch interfaces; managed component metadata and lifecycle; compatibility checks; versioned representation/fusion/head-output contracts; deterministic structural orchestration; and deterministic test fixtures. The pipeline returns nested structural envelopes only. It does not run a cognitive head or produce a cognitive prediction.

The owner priority override explicitly defers I3.1 qualification, Task A/B semantic resolution, I3.2 grammar and dataset generation, household scenario diversification, and leakage qualification. I3.3 therefore uses neutral versioned envelopes and leaves those meanings unresolved. No dataset, label, or existing I3.1 work was modified to bypass the deferral.

## Branch and fusion behavior

**Event branch:** receives I2 encoded observations, position, receipt time, availability state, and decision cutoff. It must return exactly one representation per supplied observation while preserving entity, attribute, source/provenance, evidence reference, observation time, and receipt time. Household identifiers are not defined as global learned event semantics.

**Topo-Temporal branch:** receives ordered event representations, available entities and directed relations, event-location associations, topology and history availability, optional history range, and cutoff. Partial/missing location, topology, or history are explicit. No fixed feature-vector width or room semantics are introduced.

**Home branch:** optional. Active adaptation requires an opaque adaptation reference, semantic model version, and training cutoff. Its input nests General fusion; explicit-memory version is separate. Cold-start, unavailable, reset, or unregistered adaptation does not prevent General fusion. Home runtime failure is isolated to that contribution.

**Fusion:** Event and Topo-Temporal form an ordered General envelope; Cognitive fusion nests General plus the optional Home contribution. Independent dimensions and masks remain intact. There is no concatenation, learned attention, prediction, or arbitrary risk score.

**Lifecycle:** component and schema versions are checked at registration. Replacement initializes before swapping and retains the previous component if initialization fails. Registry calls are synchronized against replacement/shutdown. It is not an OTA or persistent model registry.

## Existing MLP assessment

The existing Go adapter remains at `internal/intelligence/mlp` and consumes the frozen 86-value runtime input. Checked-in V1 bundles contain four separate 86→32 ReLU→output heads, totaling 11,994 stored weights and biases. The V3 candidate contains a shared 86→128 ReLU backbone and five output heads, totaling 15,135 stored weights and biases. These counts are derived from checked-in CPU JSON parameter arrays. V3 is a separate candidate/dry-run bundle, not the I3.3 Triple-MLP branches.

The 31-parameter I1 research experiment is separate: 3 input bits, 6 tanh hidden units, sigmoid output, and a reported 98.24% synthetic held-home accuracy. That result remains limited to the synthetic I1 task and does not validate this architecture or the Go runtime bundles. No legacy model was replaced, retrained, or adapted.
