## Scope

I3.3 installs an executable, model-independent architecture skeleton in `internal/intelligence/hybrid`. It defines three independently replaceable representation branches—Event, Topo-Temporal, and optional Home Adaptation—plus an in-process lifecycle registry, versioned envelopes, deterministic structural fusion, and typed cognitive-head output contracts.

The package does not contain neural networks, learned weights, model loading, training, or genuine cognitive predictions. Deterministic components exist only in tests and are tagged `test-fixture`; the production pipeline rejects those unless `AllowTestFixtures` is explicitly enabled. No head is invoked by `Pipeline.Run`. Results stop at structural representations and fusion envelopes.

## Data flow

1. The Event branch receives I2 encoded observations plus receipt time, order, and decision cutoff. Its output must retain entity, attribute, source/provenance, evidence reference, observed time, receipt time, and input position.
2. The Topo-Temporal branch receives those ordered event representations, available directed relations/entities, event-location associations, topology/history availability, history interval, and cutoff. It must return a versioned representation. Partial or unknown context remains explicit.
3. General fusion stores the Event and Topo-Temporal contributions in fixed role order. It preserves each event record and each branch representation, including their own vector dimension and validity mask. It does not concatenate vectors, compute attention, infer room meaning, or calculate risk.
4. If home adaptation is available, the optional Home branch receives a deep copy of General fusion plus an opaque adaptation reference, model version, explicit-memory version, and training cutoff. Its representation is nested as the Home contribution in Cognitive fusion. If home is cold-start, reset, unavailable, or unregistered, General fusion remains available and Cognitive fusion records that state.
5. Cognitive head contracts describe later assessment, event/risk prediction, and domestic-assistance outputs. They validate outcome, uncertainty, evidence references, component provenance, and no-event/no-action/abstain forms. They provide no authorization or dispatch operation and are not called by the current pipeline.

## Installed contracts and behavior

The schema constants in `types.go` version Event, Topo-Temporal, Home, Head, Representation, Fusion, and Head Output boundaries independently from `ArchitectureVersion` and per-component versions. Component metadata also identifies execution class (`test-fixture`, `untrained-adapter`, or `trained-model`); trained components require a semantic-versioned model version. Representation dimensions are runtime metadata rather than a fixed feature layout.

The registry initializes components independently, exposes sorted lifecycle records, rejects duplicate IDs and mismatched interfaces/schema versions, and allows replacement after the new component initializes. Failed replacement initialization leaves the prior component active. Calls are serialized against replacement/shutdown; runtime failures are recorded. A component's metadata is checked for mutation after registration. This is a lightweight in-process registry, not an artifact store, OTA updater, or deployment manager.

Validation rejects post-cutoff receipt times for events, entities, relations, and known locations. `observed_at` is retained as supplied and can be later than the decision cutoff; this is not treated as evidence that the record was available late. Topology may be complete, partial, unknown, or unavailable; history may be available, partial, insufficient, or unavailable. No room-type or household semantic rules are imposed. Complete topology requires entity endpoints for supplied relations and known event locations.

Inputs passed to branches are deep-copied. Topology entities, relations, and location associations are put into deterministic order before the Topo-Temporal branch call. Ordered event positions remain caller-defined and validated. Home branch runtime failure is isolated and reported in its contribution; failure of either required general branch returns an explicit error.

## Boundaries

- State Encoder behavior and its structured I2 output are unchanged.
- Foundation remains authoritative for explicit persisted household facts; the Home branch contract does not make weights authoritative.
- This package has no Cognitive Core dependency and no production action path. Core policy and safety gate behavior are untouched.
- Event semantics must be global. Household identity is not an event semantic feature contract; opaque household adaptation references belong only to the optional Home boundary.
- No online learning, retraining, resident profiling, continuous polling, background inference, or actuation is implemented.
- No dataset artifacts, labels, Task A/B meaning, or transition timing were changed or resolved.

## Existing model inventory (preserved)

The existing Go inference adapter is `internal/intelligence/mlp`; it adapts already-built CPU model bundles and is separate from this new architecture. The checked-in V1 CPU bundle uses a frozen 86-value input with four independent dense heads (11,994 total parameters across the checked-in heads). The V3 candidate uses a shared 86→128 ReLU backbone and five output heads (15,135 parameters in the checked-in candidate bundle); it is a candidate/dry-run artifact, not the new Triple-MLP design. These counts sum the stored weight and bias values in the checked-in JSON artifacts. Existing adapter tests remain in place; I3.3 neither replaces nor modifies this adapter or its bundles.

The 31-parameter I1 experiment in `research/i1/next_state_experiment.py` is a distinct synthetic research model (3 inputs, 6 tanh hidden units, one sigmoid output). Its reported 98.24% synthetic held-home test accuracy is not an operational result for the Go adapter or this Triple-MLP architecture. Preserve its report and limitations unchanged.
